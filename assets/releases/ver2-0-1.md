# Tutor v2.0.1 Draft Release Notes

**Release Date:** Unreleased

v2.0.1 continues the production-readiness pass on Tutor's single course
workspace. It keeps the product surface narrow while refining the creator and
reader so the app feels more like a focused learning tool than a migrated
dashboard.

## Highlights

### Course Creator Setup Clarity

- **Single owner for starting prompts** - the left rail keeps recent courses and
  starting prompts, removing repeated prompt lists from the creator workspace.
- **Live course plan summary** - the right rail now summarizes selected format,
  length, complexity, focus, and attached source state before generation.
- **Quieter right rail** - the reader promise is folded into the course plan so
  setup context stays in one calm surface instead of competing cards.
- **Clear setup controls** - the creator toolbar now labels the setup toggle by
  what it actually opens and keeps text-button accessible names aligned with
  visible labels.
- **Nearby advanced settings** - length, complexity, and focus controls now
  expand directly below the prompt composer instead of appearing after the
  source step on smaller screens.
- **Source state visibility** - attached files now appear as removable rows in
  the Add Sources panel itself, so the main source step confirms what Tutor will
  use and lets learners correct the list before generation.

### Course Reader Visual Polish

- **Quieter reader rails** - the desktop reader now uses the contents and
  sources rails for structure instead of stacking extra article divider lines.
- **More durable lesson titles** - lesson headings keep a readable measure on
  mobile and desktop instead of forcing overly narrow wrapping.
- **Compact mobile actions** - the mobile header keeps the course title as the
  primary signal while preserving accessible names for Sources and New Format.
- **Source dialog polish** - the reader Sources panel now opens as a named
  dialog with a source-count summary and standard Escape/backdrop dismissal.
- **Course contents drawer polish** - the reader table of contents now has a
  visible dialog title, section summary, close button, and Escape/backdrop
  dismissal.
- **Artifact overlay polish** - generated course artifacts now open in named
  fullscreen dialogs with a consistent icon close control and Escape dismissal,
  and artifact launches from the contents drawer no longer leave stacked dialogs.
- **Reader input accessibility** - the sticky question composer, Go Deeper
  prompt field, and section audio controls now use localized accessible names
  instead of relying on placeholders or hardcoded labels.
- **Cleaner control names** - section navigation rows, quiz answer choices, and
  reader progress now expose localized accessible names instead of concatenating
  visual fragments.
- **Focused Add Format dialog** - the reader's format picker now uses localized
  format cards with short purpose descriptions and removes the inactive upload
  affordance, with named dialog semantics and Escape/backdrop dismissal.
- **Workspace-matched loading chrome** - reader loading and audio controls use
  the same warm Tutor palette as the rest of the course surface.

### Production Dependency Hardening

- **Clean frontend audit** - the web lockfile now resolves patched
  `dompurify@3.4.11` and `undici@7.28.0`, clearing the current moderate and
  high npm advisories without changing Tutor's dependency manifest.
- **Safer settings diagnostics** - settings save/apply responses and provider
  diagnostic events now mask configured API keys while preserving the in-memory
  editor draft, so successful tests no longer echo raw credentials through the
  browser event stream.
- **Polished provider configuration** - Settings now presents active
  provider/model/endpoint state as a configuration panel with provider presets,
  hidden-key status, clearer running/disabled actions, search result limits,
  and embedding timeout/batch controls that are used by the runtime.
- **Course generation works in the production image** - the Docker image now
  includes the Markdown prompt templates that Next.js route handlers load at
  runtime, fixing production `course-outline` 500s caused by missing prompt
  files.
